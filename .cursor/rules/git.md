# Git 工作流规则

## 提交规范
- 提交信息使用中文，格式：`类型: 简短描述`
- 提交类型：
  - `feat`: 新功能
  - `fix`: 修复bug
  - `docs`: 文档更新
  - `style`: 代码格式调整（不影响功能）
  - `refactor`: 代码重构
  - `perf`: 性能优化
  - `test`: 测试相关
  - `chore`: 构建/工具链相关
- 示例：`fix: 修复登录器连接超时问题`

## 分支管理
- 主分支：`main` 或 `master`
- 功能分支：`feature/功能名称`
- 修复分支：`fix/问题描述`
- 提交前确保代码可以编译通过

## 文件忽略
- 不要提交编译生成的文件（.exe, .dcu, .obj 等）
- 不要提交临时文件和备份文件
- 不要提交第三方库的源代码（demmrfm 目录）
- 注意 .gitignore 文件的维护

## 代码审查
- 提交前检查代码格式和命名规范
- 确保没有硬编码的路径和配置
- 检查是否有内存泄漏风险
- 确保异常处理完善
