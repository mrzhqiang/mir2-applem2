# 文档编写规则

## 代码注释
- 公共接口必须有注释说明
- 复杂算法必须有注释
- 业务逻辑使用中文注释
- 注释要清晰准确，不要冗余
- 示例：
  ```pascal
  {*
    用户登录验证
    @param UserName 用户名
    @param Password 密码
    @return 登录成功返回 True，失败返回 False
  *}
  function Login(const UserName, Password: string): Boolean;
  ```

## 单元文档
- 每个单元文件开头说明单元用途
- 列出主要类和函数
- 说明依赖关系
- 示例：
  ```pascal
  unit UserManager;
  
  {*
    用户管理单元
    负责用户的创建、登录、权限验证等功能
    
    主要类：
    - TUserManager: 用户管理器
    - TUser: 用户对象
    
    依赖：
    - Common: 公共函数
    - Database: 数据库操作
  *}
  ```

## API 文档
- 说明函数参数和返回值
- 说明函数用途和使用场景
- 提供使用示例
- 说明可能的异常

## 配置文档
- 说明配置文件格式
- 列出所有配置项及其含义
- 提供配置示例
- 说明默认值

## README 文档
- 项目概述和用途
- 编译和运行说明
- 依赖项列表
- 常见问题解答
- 更新日志

## 设计文档
- 系统架构说明
- 模块设计说明
- 数据流说明
- 接口设计说明

## 变更文档
- 记录重要变更
- 说明变更原因
- 列出影响范围
- 提供迁移指南

## 文档格式
- 使用 Markdown 格式
- 使用清晰的标题层级
- 使用代码块展示示例
- 使用列表组织内容
- 添加必要的图表

## 文档维护
- 代码变更时同步更新文档
- 定期审查文档准确性
- 保持文档简洁明了
- 及时删除过时内容
